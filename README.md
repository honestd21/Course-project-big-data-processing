# Описание предметной области и исходных данных

**Дисциплина:** Б1.В.14 «Большие данные в сельском хозяйстве», курсовой проект

**Направление курсового проекта:** «Качество и предобработка данных, подходы и инструменты»

**Предлагаемая тема:** Оценка качества данных и автоматизация их проверки в задаче прогнозирования урожайности сельскохозяйственных культур и влияние дефектов данных на качество моделей машинного обучения

**Исходный набор данных:** Kaggle, `patelris/crop-yield-prediction-dataset` (итоговая таблица `yield_df.csv` и четыре исходных файла, из которых она собрана)

---

## 1. Предметная область

Прогнозирование урожайности сельскохозяйственных культур по климатическим и агротехническим факторам.

- **Прикладная задача:** оценить урожайность культуры для страны и года по осадкам, температуре и использованию пестицидов.
- **Значимость:** планирование производства и поставок, оценка продовольственной безопасности, анализ влияния климата на урожайность.
- **Тип данных:** табличные панельные данные: ключ (страна × культура × год), признаки (осадки, температура, пестициды), целевая переменная (урожайность).
- **Источники:** статистика FAO (файлы урожайности и пестицидов имеют структуру выгрузок FAOSTAT), климатические данные по странам.
- **Проблема качества данных:** международная статистика собирается из нескольких источников. При объединении возникают дубликаты, конфликты значений, пропуски и расхождения форматов. От этого зависят метрики модели и достоверность выводов.

## 4. Почему выбран этот набор данных

- Задача из АПК, данные международной статистики FAO.
- Табличный формат среднего размера: считается быстро, без GPU, подходит для сравнения моделей.
- Данные собраны из нескольких источников, поэтому реальные дефекты (дубликаты, конфликты, пропуски, константы) уже есть и подтверждены измерениями.
- Строки одной страны похожи друг на друга, поэтому при случайном разбиении страна попала бы и в обучение, и в тест, а оценка качества получилась бы завышенной. Структура «страна × год» позволяет разбивать данные по странам и оценивать качество на не виданных странах.
- Доступны как итоговая таблица, так и исходные файлы, что даёт возможность воспроизвести сборку и найти причины дефектов.
- По набору существуют научные публикации, их можно использовать в обзоре литературы.

## 5. Цель и задачи

**Цель:** разработка прототипа системы оценки и автоматической проверки качества данных для прогнозирования урожайности сельскохозяйственных культур с использованием методов машинного обучения и Python-инструментария.

**Задачи:**
1. Изучить теоретические основы качества данных, виды дефектов и методы их обнаружения в задачах прогнозирования урожайности (обзор литературы).
2. Выполнить профилирование итоговой таблицы `yield_df.csv`, подтвердить числами дефекты из описания набора и описать их.
3. Разработать набор автоматических правил проверки качества (уникальность ключа, константность признака внутри страны, согласованность температуры внутри страны и года, выбросы и асимметрия распределений, пропуски) с единым отчётом и провести мини-тесты.
4. Разработать процедуру очистки данных по всем правилам проверки, получить три состояния данных (исходные, без дублей, полная очистка) и вести лог по правилам.
5. Реализовать контролируемую порчу очищенной таблицы по каждому правилу (пропуски, конфликт температуры внутри пары «страна, год», дубликаты ключа, выбросы, константные осадки) на одном уровне 5 % и по известной маске внесённых дефектов оценить полноту обнаружения и долю ложных срабатываний правил проверки.
6. Обучить модели (Ridge, RandomForest, HistGradientBoosting) на трёх состояниях данных (исходные, без дублей, полная очистка) при разбиении по странам (GroupKFold) и оценить влияние дефектов данных на MAE, RMSE, R² (эксперимент A).
7. Проанализировать результаты (ошибки по странам и культурам, важность признаков, сравнение метрик по состояниям данных).
8. Сформулировать выводы, ограничения и рекомендации.

## 6. Что сравниваем

**Эксперимент A (влияние дефектов на модели)**

| Что | Варианты |
|-----|----------|
| Состояние данных | исходные; после удаления дублей; после полной автоматической очистки |
| Модели | Ridge-регрессия, Random Forest, HistGradientBoosting |

**Оценка правил проверки (контролируемая порча)**

| Что | Варианты |
|-----|----------|
| Вид дефекта | пропуски (R4), конфликт температуры (R2), дубликаты ключа (R1), выбросы (R3), константные осадки (R5) |
| Уровень внесённых дефектов | один уровень, 5 % единиц порчи (строк, пар «страна, год» или стран), фиксированный seed |

Осадки в очищенной таблице отсутствуют (столбец удалён правилом R5), поэтому порча R5 проверяется на синтетических осадках, меняющихся по годам. Пропуски вносятся случайно, без разбора механизмов MCAR, MAR, MNAR.

## 7. Метрики и протокол

- **Метрики модели:** MAE, RMSE, R².
- **Метрики проверок качества:** полнота обнаружения внесённых дефектов, доля ложных срабатываний, число нарушений правил до и после очистки.
- **Устойчивость:** несколько запусков с разными seed, среднее ± разброс.
- **Воспроизводимость:** фиксированный seed, логирование экспериментов.
- **Анализ ошибок:** по странам и культурам, график остатков, важность признаков, при наличии координат карта ошибок по странам.
- **Валидация:** разбиение по странам (GroupKFold); предобработка внутри `Pipeline` только на обучающей части.
